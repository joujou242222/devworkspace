## 7. Infrastructure and security boundaries

Compose includes PostgreSQL, Redis, SeaweedFS, Mailpit, proxy and three application processes. Images are version/digest pinned. A private internal network and no nonproxy published ports are statically checked; only 127.0.0.1:8443 is published. Compose runtime, firewall reachability and service resource use are not proven because Docker is absent. Dockerfile/Compose must be executed before this infrastructure criterion is closed.

The proxy routes REST/auth and Socket.IO to the API, other web paths to Next, and only shape-checked signed staging PUT requests toward private S3. It denies canonical/admin reads and strips cookies on staging. Wrong Origin/method and forbidden reads have real rejection tests. Successful S3 signature preservation, conditional writes, checksum/cap enforcement and canonical immutability are **NOT TESTED**. They remain V03/Phase 4.

No bucket bootstrap, scoped upload capability or production storage permission exists. Ignored local S3 admin credentials initialize a disposable candidate only. The configured 25 MiB proxy header cap does not prove end-to-end file capacity. 100-page PDF and 2 MiB avatar defaults are also unverified.

Experiment registration/login is intentionally exposed only in the gated local experiment; it has no organization plugin, roles, product schema, migration, RLS, production audit/outbox, or production security claim. Environment validation refuses enabling it with NODE_ENV=production.
