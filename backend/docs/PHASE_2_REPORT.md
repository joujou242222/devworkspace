Session tokens retain the library’s signed-cookie/plain-database-token representation behind the restricted identity role; no unsupported token-hashing adaptation is claimed. Login rotates the presented same-user session; logout, password reset, own-session revocation and membership privilege transitions revoke database sessions. - All unsafe product requests require exact Origin and a cryptographic CSRF token bound to a host-only nonce cookie and the current session cookie. A public same-origin bootstrap endpoint acquires the token before login. SameSite alone is not the defense. Redirects use a bounded relative allowlist; proof queries are removed from browser history. No product state-changing GET or raw library handler is exposed.
- Own-account APIs select the user from the validated session, return explicit public fields, reject unknown fields, use revisions for profile edits, and expose session metadata without bearer tokens. Another user's session cannot be revoked. Protected server pages forward only current cookies to the fixed local API with no shared cache; browser reads revalidate live access.
- Organization creation atomically writes Organization, first Owner, sensitive audit, outbox, delivery intent and a self-scoped onboarding receipt. Matching retries return the existing organization after current authorization; changed payloads conflict. Audit failure rolls all effects back.
- Explicit selected internal principals resolve only active memberships. Every tenant request loads the chosen organization, revalidates session and membership on the same transaction, applies field/role policy and serializes relevant authority changes. Client capacities await real Client/Project models in Phase 3.
- Owner/Admin team management supports real internal invitations, immutable role/email/issuer binding, expiry, revocation, verified intended acceptance, live issuer authority and repeat-safe acceptance. No Owner/client target can be overposted into an internal invite. Membership/acceptance/audit/event/receipt commit together. ## Audit, outbox, native mail and recovery

Sensitive tenant commands commit audit/event/receipt with the domain mutation. Identity-table triggers append safe identity audit and security event intents. Failed/denied requests use a separately bounded, redacted correlation log rather than a rolled-back domain audit insert. Logs omit cookies, passwords, proof URLs, signed queries and content. API errors use safe `application/problem+json` with request IDs, while generated DTOs omit ORM records/session secrets.

Mail capabilities are AES-256-GCM encrypted in dedicated restricted mail tables. Public outbox envelopes, dispatch rows and BullMQ jobs contain references, scope and leases; no proof link is placed in queue payloads. Registration/recovery callbacks use the pinned core adapter transaction context so identity writes, proof/mail and audit/outbox intent are atomic. A per-operation failure flag detects the library's swallowed callback errors and forces rollback with a recoverable error.

The worker claims only committed rows, enqueues stable event/lease references, validates the trusted reference, sends actual SMTP to Mailpit, and commits a unique consumer receipt/completion. PostgreSQL retains incomplete leases/attempts; accepted-but-lost queue work can be claimed again after expiry. Retries use persisted backoff capped at five minutes, an eight-attempt budget and visible exhausted state. Local operators can use `phase2:mail-status` and the narrow failed-only `phase2:mail-retry` command. Completed work cannot be reset through that interface; retries append dispatch audit. SMTP can succeed before receipt persistence, so duplicate mail remains possible. The links remain expiring/one-time; no exactly-once delivery claim is made.

Recovery instructions are in [infra/README.md](../infra/README.md). Preserve ignored role credentials/mail encryption key with private database backups. Rerun preparation to verify/retry missing migrations; add forward repairs rather than modifying history. Existing database/native files are never deleted by product startup. Full backup/restore, production deployment, global hardening and V08 remain outside Phase 2.

### Failures investigated and corrected

1. Initial role/function ownership and migration-ledger grants were insufficient. Migration metadata moved to an admin-owned schema; narrow function owners receive CREATE only during transfer, then lose it. Product setup now repeats safely.
2. Shared trigger records accessed fields absent on another trigger table. Forward migration `0003` uses explicit JSON field extraction; real registration/audit/mail then persisted.
3. Cairo-cluster timezone interpretation shifted product timestamps by three hours and immediately invalidated sessions. Product pool connections now explicitly use UTC; idle/absolute/recent-auth tests pass against actual stored instants.
4. Better Auth catches callback failures. Fault injection exposed a misleading success after an aborted mail insert. The transaction boundary now observes a per-operation callback failure flag and returns 503 with no partial identity/credential/audit/outbox effects.
5. Browser verification found a populated textarea's accessible label needed an explicit name. The corrected interface passes real settings save/reload. A test locator was also scoped to the main content to avoid Next.js's separate route-announcer alert.
6. An initial legacy two-process run could not start its second API during intermediate builds. A later direct startup probe and unchanged full 20-test regression pass establish the final retained behavior; the failed intermediate run is not counted as evidence.
7. Native regression reached S3 before SeaweedFS had registered retained volumes. Logs showed the object read failing at 19:08:27 and the volume heartbeat at 19:08:28 in that process's log timezone. Existing bytes were retained; the test's own cleanup removed only its synthetic object. Readiness now checks master topology against retained volume IDs, with a focused unit regression, before declaring startup ready. No binary/configuration/data reset was used.
